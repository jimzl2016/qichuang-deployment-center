# 运营管理系统 EXE 安装器重设计

## 目标

将现有启创动力部署中心重设计为 720×540 像素的桌面 EXE 安装向导界面。页面采用左侧步骤、右侧表单的固定布局，每个步骤的内容必须在一屏内完成展示；字段较多时使用当前步骤内部的 Tab，不使用页面纵向滚动。

本设计覆盖旧规格中的整体布局、主题模式、标题和内容组织方式。部署状态机、敏感信息安全约束、环境检测、部署失败恢复、交付清单下载以及部署完成后禁止返回的规则继续保留。

## 窗口与布局

- 安装器画布固定为 720×540 像素。
- 左侧步骤栏固定宽度 180 像素，右侧内容区固定宽度 540 像素。
- 右侧内容区按三行组织：84 像素步骤标题、394 像素当前步骤内容、62 像素底部操作栏。
- 实际 EXE 窗口不出现页面级滚动条。
- GitHub Pages 预览在宽屏中居中展示 720×540 安装器画布；视口小于画布时等比缩小整个画布，仅用于预览，不改变 EXE 的目标尺寸。

## 品牌与视觉

- 页面标题改为“运营管理系统安装”。
- 左侧顶部展示启创动力品牌。沿用用户提供的橙色 Logo，在标志容器中增加蓝色视觉强调，形成橙色与蓝色组合。
- 左侧步骤栏使用明快但稳定的深蓝色，当前步骤使用白色圆形编号和高亮文字，未完成步骤使用低对比蓝灰色。
- 右侧使用白色表单背景和浅蓝灰分区背景。
- 品牌橙用于主要操作按钮和关键进度，品牌蓝用于 Tab、焦点、链接、选中状态和信息提示。
- 成功、警告和失败继续分别使用绿色、黄色和红色。
- 移除暗色/亮色切换控件和全部主题持久化逻辑，仅保留单一明亮主题。
- 文案保持简短，不显示英文大标题、功能介绍或冗长说明。

## 左侧步骤栏

左侧固定展示三个步骤：

1. 部署目标
2. 安装与部署
3. 完成安装

步骤之间使用细线连接。当前步骤、已完成步骤和未开始步骤具有明确状态。步骤遵循现有门禁：不能跳过未完成步骤；进入完成安装后，前两步锁定且不能返回。左侧底部展示安装器版本。

## 右侧通用结构

### 标题区

标题区展示当前步骤编号、中文标题和一句短说明。标题不超过一行，说明不超过两行。

### 内容区

内容区仅显示当前步骤。字段采用两列紧凑网格；密码输入保留显示/隐藏控制。字段组过多时使用 Tab，Tab 只切换当前步骤内部内容，不改变部署步骤。

### 操作栏

底部操作栏固定在窗口底部，按钮不会因 Tab、校验信息、日志或清单内容移动。主要操作在最右侧，次要操作位于其左侧。

## Step 1：部署目标

内容区使用“远程 SSH”和“本机部署”两个 Tab。

### 远程 SSH Tab

显示：目标名称、服务器地址、SSH 端口、登录用户、密码/私钥认证切换，以及对应的 SSH 密码或私钥路径和私钥口令。

### 本机部署 Tab

显示：数据库 Owner、远程 openGauss 地址、openGauss 端口、运维用户名和运维密码。

### 环境预检

底部操作为“检查环境”和“下一步”。点击检查后，内容区底部显示 Docker、架构、磁盘和权限四个紧凑状态项，不扩展窗口高度。全部通过后才能进入下一步。

## Step 2：安装与部署

内容区使用三个 Tab：

1. 运行材料：Runtime Bundle 版本、云效 Generic 用户名、云效密码或令牌。
2. 镜像仓库：Harbor 用户名、Harbor 密码或机器人令牌、简短安全说明和故障演示开关。
3. 部署进度：总体进度、当前任务、已用时间、紧凑终端日志和部署失败内联提示。

底部操作为“上一步”和“开始部署”。开始部署前校验前两个 Tab 的全部必填字段；若错误字段位于非当前 Tab，自动切换到对应 Tab并聚焦首个错误字段。开始后自动切换到“部署进度”。

故障演示仍在拉取镜像阶段触发 `DEPLOY-IMG-401`。错误面板在部署进度 Tab 内显示，提供“修改认证信息”和“重新部署”。“修改认证信息”自动切换到镜像仓库 Tab并聚焦 Harbor 用户名。

## Step 3：完成安装

完成页使用三个 Tab：

1. 部署信息：部署目标、运行根、Runtime Bundle 版本和部署时间。
2. 数据服务：关系数据库和时序数据库的地址、端口、用户名、密码或令牌。
3. 文件与后台：MinIO 服务和控制台地址、Access Key、Secret Key，以及后台系统地址和管理员凭据。

清单以紧凑的标签和值布局展示，密码和令牌默认遮罩，支持显示/隐藏和单项复制。底部固定操作为“下载交付清单”和“登录系统”。进入此步骤后不显示上一步操作，左侧前两步不可点击。

## 状态与数据流

- 保留现有单一内存状态对象，增加当前步骤内部 Tab 状态。
- 切换 Tab 不清空已填写字段、检测结果、部署日志或交付凭据。
- 步骤校验失败时自动打开包含错误字段的 Tab。
- 页面刷新清除所有部署字段和敏感数据。
- 移除 `qcdl-theme` 的读取、写入和主题事件监听。
- 演示凭据继续使用浏览器随机数生成，仅存在当前内存。

## 错误处理

- 字段错误显示为紧凑红色提示，不改变固定窗口高度；同一 Tab 同时显示的提示最多保留一行。
- 环境检测失败时显示简短修复提示，并保持下一步禁用。
- 部署失败时切换到部署进度 Tab，停止计时和进度，显示脱敏错误面板。
- 错误面板和日志不得包含密码、令牌、私钥路径或口令。
- 复制和下载失败时使用短暂提示，不引入额外弹层尺寸变化。

## 技术边界

- 继续使用原生 HTML、CSS 和 JavaScript，不增加框架或构建依赖。
- 保留现有静态服务器和 GitHub Pages 部署方式。
- 重构现有 `index.html`、`styles.css` 和 `app.js`，不创建第二套独立页面。
- 通过 CSS 固定安装器画布尺寸，并使用缩放容器支持较小的网页预览视口。

## 验收标准

1. 在 720×540 视口中，安装器画布完整铺满且没有页面级或内容区滚动条。
2. 左侧宽度为 180 像素，右侧宽度为 540 像素，底部操作栏位置在三个步骤中保持不变。
3. 页面标题为“运营管理系统安装”，Logo 和界面同时呈现橙色与蓝色品牌元素。
4. 页面不包含暗色、亮色或主题切换控件，也不再访问 `qcdl-theme`。
5. Step 1 的远程 SSH 和本机部署 Tab 可以切换，字段与现有业务要求一致。
6. 环境预检四项结果在 Step 1 一屏内完整显示。
7. Step 2 的运行材料、镜像仓库和部署进度 Tab 可以切换；校验错误会打开正确 Tab。
8. 正常部署和故障演示均可完成对应流程，部署日志与错误面板不泄露敏感值。
9. Step 3 的三个清单 Tab 可访问，密码显隐、复制、下载和登录系统功能保持可用。
10. 进入 Step 3 后无法返回 Step 1 或 Step 2。
11. GitHub Pages 宽屏预览居中，小于 720×540 的视口等比缩小且不产生内容遮挡。
12. 键盘可以访问步骤、Tab、表单、密码控制和底部操作按钮，焦点清晰可见。
