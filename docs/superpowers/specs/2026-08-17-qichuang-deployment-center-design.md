# 启创动力部署中心 HTML 原型设计

## 目标

构建一个可直接在现代浏览器中运行的单页部署安装原型，帮助实施工程师按顺序完成目标环境检测、安装方式配置、项目部署模拟和部署交付清单生成。原型不执行真实系统命令，也不连接真实数据库。

## 使用对象与场景

- 使用对象：实施工程师、运维工程师、项目交付人员。
- 主要场景：部署前核验环境、确认安装参数、演示部署过程、整理交付凭据。
- 成功标准：用户可以在一个页面内完成四步流程，并下载包含全部部署信息的 TXT 交付清单。

## 信息架构

页面采用横向四步工作台：

1. 顶部品牌栏展示 Logo、产品名称“启创动力 · 部署中心”和当前节点状态。
2. 品牌栏下方展示四步进度，区分未开始、当前、已完成状态。
3. 主工作区在桌面端分为当前任务区和右侧部署摘要区。
4. 页面底部提供上一步、重新操作和下一步等上下文操作。
5. 平板和手机端切换为单栏，右侧摘要移动到当前任务下方。

## 四步流程

### 第 1 步：目标环境与环境检测

用户配置操作系统、CPU 架构和部署节点名称，然后运行模拟检测。检测项包含操作系统、CPU、内存、磁盘、Docker 引擎、网络端口和外部网络。每一项显示检测值、要求和通过、警告或失败状态。

首次进入页面时检测项处于等待状态。点击检测后逐项更新结果。演示数据默认全部满足部署要求。任何失败项都会禁用下一步并显示对应修复建议；用户可以重新检测。

### 第 2 步：安装方式

提供三种互斥安装方式：Docker 容器化部署、离线安装包和手动安装。Docker 为默认推荐选项。用户还需设置安装目录、数据目录、访问协议、访问主机和端口。

路径和主机为必填项，端口必须为 1 至 65535 的整数。校验错误显示在字段附近，并阻止进入下一步。

### 第 3 步：部署项目

展示可部署组件并默认全选：应用后台、管理前端、关系数据库、时序数据库、文件存储和反向代理。用户至少保留一个组件才能开始部署。

部署过程为前端模拟：组件依次经历等待、安装中、已完成状态；总体百分比、当前任务、已用时间和终端日志同步更新。部署完成后才能进入交付清单。页面不运行 shell 命令、不发起真实安装请求。

### 第 4 步：部署交付清单

集中展示以下交付信息：

- 部署摘要：项目名称、节点、安装方式、安装目录、数据目录和完成时间。
- 关系数据库：类型、主机、端口、数据库名、用户名和密码。
- 时序数据库：类型、访问地址、组织、存储桶、令牌或密码。
- 文件存储：类型、服务地址、控制台地址、Access Key 和 Secret Key。
- 后台系统：访问地址、管理员账号和密码。

密码和令牌默认遮罩，允许逐项显示或隐藏。用户可以复制单个值、复制完整清单或下载 UTF-8 编码的 TXT 文件。复制与下载操作后显示明确反馈，并提示用户将清单保存在受控位置。

## 数据与安全边界

- 所有表单状态仅保存在当前页面内存中，刷新页面即清除。
- 演示密码、令牌和密钥在首次进入页面时通过浏览器随机数能力生成，不在源代码中保存固定凭据。
- 页面不包含后端服务、持久化、远程请求或真实系统检测能力。
- 导出的清单属于演示数据，但界面仍按敏感信息处理并提供保管提示。

## 视觉设计

采用深色运维终端风格。背景使用近黑和深炭灰，卡片与表单使用层级更高的深灰。品牌橙用于当前步骤、主按钮、进度和焦点状态。绿色表示通过，黄色表示警告，红色表示失败。

Logo 使用用户提供的 `logo11@4x.png`，在页面内复制为本地资产并保持原始比例。界面标题字体选择清晰的中文无衬线字体栈，部署日志和技术值使用等宽字体。动效仅用于步骤切换、检测结果出现、进度更新和短暂反馈，不使用无业务意义的装饰动画。

## 交互与错误处理

- 步骤导航只能进入当前步骤或已完成步骤，不能跳过未完成步骤。
- 每一步在继续前执行本地校验；错误信息与对应字段或检测项关联。
- 检测和部署运行期间禁用会造成状态冲突的操作。
- 复制 API 不可用时，显示失败提示，不虚报成功。
- 下载由浏览器本地生成 Blob，不依赖网络。
- “重新开始”需要二次确认，确认后清空当前页面状态并返回第 1 步。

## 技术方案

交付物采用原生 HTML、CSS 和 JavaScript，避免安装依赖，双击 `index.html` 即可运行。结构划分为：

- `index.html`：语义化页面结构和四步内容。
- `styles.css`：设计令牌、布局、组件状态、动效和响应式规则。
- `app.js`：页面状态、校验、模拟检测、模拟部署、凭据生成、复制和下载。
- `assets/logo.png`：部署中心使用的品牌 Logo。

页面使用单一内存状态对象驱动步骤、表单、检测结果、组件状态和凭据信息，DOM 更新函数按功能边界拆分，避免业务状态散落在事件处理器中。

## 验收与测试

需要验证：

1. 页面可通过本地文件方式加载，Logo、样式和脚本均正常。
2. 默认流程可以从第 1 步完整走到第 4 步。
3. 未检测、检测失败、字段无效和部署未完成时无法继续。
4. 检测状态、部署组件、百分比和日志在模拟过程中保持一致。
5. 密码显隐不改变原始值，复制单项和复制全部内容正确。
6. 下载文件包含部署摘要和四类系统凭据，中文显示正常。
7. 重新开始会清除状态并生成新的演示凭据。
8. 桌面、平板和手机宽度下无文字遮挡、横向溢出或操作按钮错位。
9. 键盘可以访问步骤、表单、按钮和密码控制，焦点状态清晰可见。

## 不在本期范围

- 真实硬件或操作系统检测。
- 执行 Docker、数据库或应用安装命令。
- 后端 API、用户认证和权限控制。
- 保存、同步或恢复部署任务。
- PDF、Excel 或 Word 格式的交付报告。
